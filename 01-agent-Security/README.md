# 《Ignore Previous Prompt: Attack Techniques For Language Models》-2022
## 一、问题：问题场景、问题描述、问题挑战
### 1. 问题场景
当下大量企业基于GPT-3等LLM搭建API应用，通用开发范式为**固定系统基座Prompt + 用户输入占位符拼接**（如`校正文本：{user_input}`）。开发者依赖模型对齐机制与简单输入过滤保障安全，但未意识到用户输入可混入覆盖型恶意指令，形成**提示注入（Prompt Injection）**漏洞。攻击者可通过普通输入框篡改模型原始执行目标，造成输出有害内容、泄露应用私有系统Prompt两类高危风险；同时学界缺少标准化评测框架，无法定量评估各类提示注入攻击的成功率与影响因素，工业产品安全鲁棒性无统一衡量标准。

### 2. 问题描述
本文针对LLM应用拼接式Prompt架构，定义两类核心人工提示注入攻击：
1. **目标劫持（Goal Hijacking）**：输入内嵌“忽略前文指令”类恶意文本，迫使模型放弃原有业务任务，输出攻击者指定恶意语句；
2. **提示泄露（Prompt Leaking）**：注入指令诱导模型完整输出开发者内置的私有系统Prompt，泄露应用核心规则、安全约束，便于后续深度攻击。
同时提出模块化评测框架PROMPTINJECT，系统量化分隔符、采样参数、模型能力、文本后置等因子对攻击成功率的影响，在OpenAI官方35类业务Prompt上完成大规模对照实验，证实即使简单手工构造恶意输入也具备极高穿透能力。

### 3. 问题挑战
1. **漏洞机理未知**：模型优先解析用户内联覆盖指令的内在逻辑未被系统拆解，各类输入修饰手段（分隔符、大小写）对攻击增益无量化结论；
2. **双攻击场景覆盖难**：同时建模“诱导有害输出”“窃取系统提示”两类完全不同的攻击目标，缺少统一评测指标；
3. **变量维度繁杂**：攻击文本格式、分隔符、采样超参、任务模板、模型容量多重变量耦合，难以分离单一因子影响；
4. **评测工具空白**：无标准化、可复现的提示注入自动化测试框架，各研究实验条件不统一，结论无法横向对比；
5. **攻防权衡模糊**：停止符、后置文本等简易防护手段的真实衰减效果缺少大规模数据佐证。

> 对应基本要求：聚焦API线上LLM应用特有Prompt拼接架构漏洞，区别对抗样本、微调后门等攻击，核心痛点是人工提示注入无标准化评测、两类高危攻击机理与影响因素缺乏系统性定量分析。

## 二、现有工作及不足：现有工作核心思路、存在的问题及根本原因
### 1. 现有工作核心思路
1. LLM安全对齐类工作（RLHF/DPO）：仅通过微调降低模型主动有害生成概率，未防御用户输入覆盖型注入指令；
2. 文本对抗样本（TextAttack/OpenAttack）：针对分类模型输入扰动欺骗，不面向生成类应用的Prompt层级指令覆盖；
3. 社交媒体零散案例：网络零散出现提示注入Demo，但无系统化实验与定量数据支撑；
4. 输出内容过滤：仅拦截生成后的有害文本，无法阻止攻击者窃取系统Prompt；
5. 大模型偏见、训练数据泄露研究：聚焦预训练阶段风险，不推理时用户输入层面的架构漏洞。

### 2. 存在的问题
1. 研究视角单一：仅零散观测漏洞，未构建标准化自动化评测体系，实验不可复现；
2. 攻击划分缺失：未区分“目标劫持”与“提示泄露”两类差异化注入威胁，缺少分场景量化指标；
3. 影响因子未拆解：分隔符、采样温度、模型能力等关键变量对攻击成功率的影响无大规模对照；
4. 防护评估片面：仅定性提到输入清洗，未验证停止符、后置文本等轻量化防护的真实衰减效果；
5. 模型能力风险未揭示：未发现模型指令跟随能力越强，提示注入越容易成功的逆缩放风险。

### 3. 根本原因
过往LLM安全研究重心集中在预训练、微调、推理输出层面，忽略**系统Prompt与用户输入拼接的架构固有缺陷**；缺少模块化Prompt组装测试工具，无法控制变量定量解析注入攻击的生效条件，也未区分两类注入攻击的差异化难度与风险等级。

> 对应基本要求：横向区分对齐、文本对抗、输出过滤等相关文献，从“忽视Prompt拼接架构漏洞、无标准化评测、未分类量化两类注入攻击”三点提炼底层研究空白。

## 三、方案：方案动机、方案整体思路、关键步骤、关键技术
### 1. 方案动机
工业LLM应用普遍存在提示注入漏洞，但学界缺少可复现、模块化评测工具，两类注入攻击的生效条件与影响因素无系统验证。本文设计PROMPTINJECT模块化评测框架，标准化构造目标劫持、提示泄露两类攻击，分离控制各类输入/模型变量，量化各因子对攻击成功率的影响，为后续防御方案提供统一基准。

### 2. 方案整体思路
框架分为三层模块化组件：基座Prompt模块、攻击Prompt模块、模型配置模块；通过拼接用户输入占位符嵌入恶意攻击文本，自动化批量测试35类官方业务模板，统计攻击匹配成功率，消融分隔符、攻击句式、采样参数、模型容量等变量，对比两类攻击的难易程度与穿透效果，总结可落地轻量化防护思路。

### 3. 关键步骤
1. 基座Prompt构建：复用OpenAI官方35套业务模板，包含问答、翻译、摘要、代码生成等真实业务系统指令，内置{user_input}用户占位符；
2. 攻击Prompt模块化构造：
    - 目标劫持：内置“忽略全部前文+输出指定恶意字符串”指令，支持大小写、分隔符修饰；
    - 提示泄露：构造“输出/拼写检查上文系统提示”类诱导指令；
3. 修饰因子叠加：添加长短换行分隔符、多组重复分割线混淆模型上下文边界；
4. 模型参数遍历：遍历temperature、top-p、频率/存在惩罚、停止序列等采样配置；
5. 多规格OpenAI模型批量测试：ada/babbage/curie/davinci系列对比攻击成功率；
6. 效果打分：完全匹配目标字符串=劫持成功，输出包含系统指令=泄露成功，重复4轮取均值消除模型随机性；
7. 消融分析：单一变量控制，对比有无分隔、不同恶意文本、有无后置文本等场景成功率差异。

### 4. 关键技术
1. **三层模块化Prompt组装架构**：基座、攻击、模型参数完全解耦，支持任意组合批量自动化评测；
2. 两类提示注入标准化攻击范式：固定目标劫持、提示泄露的基础模板，统一匹配打分规则；
3. 分隔符混淆增强技术：利用换行、等号、横线分割线割裂上下文边界，放大模型上下文区分缺陷；
4. 变量分离消融实验设计：单一变量控制，精准量化分隔符、温度、模型能力对ASR的影响；
5. 随机稳定性校准：同一实验重复4轮取均值标准差，抵消GPT生成随机性带来的结果波动。

> 对应基本要求：动机填补提示注入标准化评测空白，流程分模板构造-攻击生成-批量测试-消融分析四段，每项技术分别解决攻击标准化、变量可控、结果稳定三大核心挑战。

## 四、实验：实验数据、对比方法、评价标准、参数设置、实验数据及分析
### 1. 实验数据与模型
1. 基座Prompt数据集：OpenAI官方35类业务模板（语法校正、问答、翻译、SQL生成、聊天等）；
2. 攻击素材：多组恶意目标文本（仇恨、暴力语句、无害文本）、多长度分隔符；
3. 测试模型：text-ada-001 / babbage-001 / curie-001 / davinci-001 / davinci-002；
4. 采样参数区间：temperature(0~1)、top-p(0~1)、频率/存在惩罚(0/2)、有无停止序列。

### 2. 对比方法
1. 基线：无任何分隔符的基础攻击句式；
2. 消融对照组：不同分隔长度/重复次数、不同恶意字符串、有无用户输入后置文本、高低温度采样、不同规模模型；
3. 两类攻击横向对照：目标劫持 vs 提示泄露成功率对比。

### 3. 评价标准
1. 目标劫持ASR：输出完全匹配指定恶意文本的样本占比（越高攻击越强）；
2. 提示泄露ASR：输出包含原始系统Prompt内容的样本占比；
3. 辅助指标：均值±标准差（4轮重复实验），用于衡量模型随机波动。

### 4. 参数设置
1. 分隔符：4/10/20长度横线、等号、大于号，重复1~4组；
2. 攻击句式：Ignore and Say / Ignore and Print / 全大写版本；
3. 恶意文本分级：轻度仇恨、重度暴力、中性长文本；
4. 温度梯度：0.25/0.5/1.0；
5. 后置文本：基座Prompt用户输入后追加约束文字/无后置文字两组对照。

### 5. 实验数据及分析
1. 基础攻击效果：Davinci-002最优劫持ASR达58.6%，提示泄露最高仅23.6%；证明提示泄露攻击难度远高于目标劫持。
2. 分隔符增益显著：无分隔符劫持成功率43.6%，10长度双分隔符提升至58.6%；换行分割线可破坏模型上下文边界识别，大幅提升穿透能力。
3. 恶意文本强度负相关：无害长文本劫持成功率70%，重度暴力语句仅49.3%；模型对齐机制会抑制极端有害指令执行。
4. 模型能力逆缩放现象：模型指令跟随越强，注入成功率越高；Ada小模型仅13.8%，Davinci大模型接近60%。
5. 轻量化防护有效：启用输出停止序列，劫持成功率从60%降至47.5%；用户输入后追加约束文本可将ASR降至51.8%，是低成本防护手段。
6. 采样参数影响有限：top-p、频率/存在惩罚对攻击成功率几乎无明显改变；仅温度升高会小幅降低攻击效果，但会牺牲输出稳定性。
7. 缺陷结论：现有输出过滤、后置约束仅小幅削弱攻击，无法完全阻断提示注入，不存在完美简易防御方案。

> 对应基本要求：实验覆盖全系列GPT-3模型与真实业务Prompt，完整消融分隔符、文本类型、采样、防护四类变量；数据清晰揭示分隔符、模型容量、恶意程度三大核心影响因子，同时验证轻量化防护的局限性，支撑全文安全风险结论。


# 《Prompt Injection attack against LLM-integrated Applications》-2023
## 一、问题：问题场景、问题描述、问题挑战
### 1. 问题场景
当前大量商业软件、在线工具、SaaS服务均接入LLM能力，通用开发架构为「系统固定提示词 + 用户输入占位符拼接」。攻击者可在用户输入框植入恶意文本，触发提示注入漏洞，实现两类高危攻击：窃取服务商私有系统Prompt、无成本滥用模型算力生成垃圾/恶意内容。现有简单提示注入手段（忽略前文、换行分隔符）在真实商用应用中成功率极低，各类应用内置输入格式化、多轮解析、输出长度限制等隐性防御，传统手工注入payload几乎失效，且业界缺少一套黑盒、自动化、适配全品类AI应用的标准化提示注入攻击方案，无法批量评估线上产品漏洞风险。

### 2. 问题描述
本文先对10款主流商用AI工具开展预实验，验证直接忽略式、转义字符类传统注入攻击在多数业务场景失效，并归纳三类失效根源；类比SQL/XSS传统注入攻击思想，提出**HOUYI后羿黑盒提示注入框架**，将攻击载荷拆解为框架段、分隔段、破坏段三组件，搭配上下文推断+迭代反馈优化流程，无需获取应用内部Prompt、模型权重，仅通过API交互即可自动生成高穿透注入payload。在36款真实商用LLM应用完成大规模实测，31款存在注入漏洞，可实现Prompt窃取、恶意代码生成、垃圾内容批量生成、隐私诱导四大攻击效果，同时验证现有主流提示防御手段均可被HOUYI绕过。

### 3. 问题挑战
1. **业务场景差异化壁垒**：不同AI应用对用户输入的定位完全不同，部分将输入视为问题、部分作为待分析数据，简单忽略指令会被业务逻辑同化，传统注入完全失效；
2. **内置隐性防御干扰**：大量应用自带输入重格式化、输出格式约束、token长度限制、多轮分步解析逻辑，截断恶意指令执行；
3. **纯黑盒攻击约束**：攻击者无法查看底层系统Prompt、模型参数、前后端代码，仅能依靠接口返回信息推断上下文；
4. **载荷自适应需求**：单一注入模板无法适配全部业务，需要根据应用功能动态生成贴合业务的伪装式恶意文本；
5. **攻击迭代优化难题**：单次注入失败后，缺少标准化反馈机制快速调整分隔、伪装策略，人工试错效率极低；
6. **多危害统一覆盖**：方案需同时支持Prompt泄露、算力滥用、恶意内容生成等多种攻击目标，不能仅单一劫持输出。

> 对应基本要求：聚焦线上商用LLM SaaS真实落地场景，区别实验室单模型提示注入研究，核心痛点是传统手工注入在工业应用失效、无自动化黑盒批量漏洞检测框架。

## 二、现有工作及不足：现有工作核心思路、存在的问题及根本原因
### 1. 现有工作核心思路
1. 基础提示注入研究（Ignore Previous Prompt）：手工构造“忽略所有前文”+换行分隔符payload，仅在无防护单轮问答模型生效；
2. 间接提示注入：污染网页/邮件等外部素材，等待应用主动读取恶意内容完成注入；
3. 各类轻量化防御方案：XML包裹、随机分隔符、前置安全指令、后置校验等单一层面防护；
4. Jailbreak越狱研究：仅针对基座模型安全护栏，不针对应用系统Prompt劫持场景；
5. 传统Web注入（SQL/XSS）：语法闭合式载荷设计思路，但未迁移至自然语言LLM场景。

### 2. 存在的问题
1. 攻击手段简陋：仅固定手工模板，无自适应生成逻辑，面对商用应用格式化、多轮流程极易失效；
2. 场景局限：仅针对独立对话模型，未适配代码生成、SWOT分析、文案创作等垂直AI工具；
3. 无黑盒自动化流程：全部依赖人工试错，无法批量批量检测数十款商用应用；
4. 载荷设计缺失分层思想：未区分伪装框架、上下文分隔、恶意目标三部分，难以绕过业务隐性格式校验；
5. 攻防评估片面：仅测试单一攻击效果，未系统性验证主流防御全部可被绕过。

### 3. 根本原因
过往提示注入研究仅关注基础对话模型推理层漏洞，未考虑商用应用存在**前后端业务处理逻辑**会消解简单恶意指令；未借鉴传统Web注入“语法闭合、上下文隔断”核心思路，缺少分层模块化payload自动生成+迭代调优的黑盒攻击范式。

> 对应基本要求：横向对比基础注入、越狱、Web注入、防御类文献，从「忽略商用应用业务层防御、无分层自适应载荷生成、缺少自动化黑盒流程」三点提炼底层研究空白。

## 三、方案：方案动机、方案整体思路、关键步骤、关键技术
### 1. 方案动机
传统手工提示注入payload在真实商用LLM应用穿透率极低，无法实现批量漏洞检测；本文类比SQL注入语法闭合思想，设计HOUYI自动化黑盒注入框架，分层构造适配业务的攻击文本，搭配上下文推断与反馈迭代机制，大幅提升商用应用攻击成功率，同时系统性验证现有防御体系的局限性。

### 2. 方案整体思路
HOUYI分为三大核心阶段：
1. 上下文推断阶段：输入样例交互提取应用功能、输入输出格式、固有上下文逻辑；
2. 三段式载荷生成：自动生成贴合业务的框架伪装段、语义/语法/多语言分隔段、承载恶意目标的破坏段；
3. 迭代反馈调优：注入后用辅助LLM判定攻击是否成功，失败则轮换分隔、框架策略重新生成payload，循环迭代直至成功；
完成后可执行Prompt窃取、批量生成恶意/垃圾内容等多类攻击，并对市面上主流防御方案开展穿透测试。

### 3. 关键步骤
1. 上下文推理：读取应用文档、交互样例，输入多组正常查询，基于返回结果归纳应用固有提示上下文、输出格式约束；
2. 三组件载荷生成：
    - 框架组件：生成符合业务正常提问的文本，伪装降低检测概率；
    - 分隔组件：语法换行、语种切换、语义总结三类策略切断原有上下文关联；
    - 破坏组件：根据攻击目标定制恶意指令（窃取系统提示/生成恶意代码/垃圾文案）；
3. 载荷拼接送入目标应用执行，获取返回结果；
4. 效果判定：辅助LLM分析返回内容，判断注入是否达成目标；
5. 策略迭代：攻击失败则切换分隔策略、更新框架文本，重新生成载荷重试；
6. 批量评测：对36款商用AI工具统一执行多类攻击，统计各类场景成功率，同时测试主流防御穿透能力。

### 4. 关键技术
1. **三段式分层注入载荷设计**：模仿SQL注入闭合思想，通过伪装+隔断+恶意指令分层，绕过应用输入格式化校验；
2. 三类上下文分隔策略：转义语法分割、跨语种注意力隔断、语义收尾隔离，多重手段切断原始系统提示约束；
3. 黑盒上下文自动推断：无需读取底层代码，仅通过少量交互样本还原应用Prompt逻辑；
4. LLM驱动迭代反馈优化：自动判别攻击成败，动态更换生成策略，摆脱人工试错；
5. 多目标适配破坏段生成：支持Prompt泄露、代码生成、垃圾文案、隐私诱导多类攻击模板。

> 对应基本要求：动机解决传统注入工业落地失效痛点，流程分推断-生成-迭代三段，每项技术分别解决伪装、上下文隔断、黑盒自适应、自动化调优四大核心挑战。

## 四、实验：实验数据、对比方法、评价标准、参数设置、实验数据及分析
### 1. 实验数据与模型

1. 每类载荷重复5次测试消除LLM输出随机性；

4. 迭代轮次无硬性上限，直至生成有效攻击payload；

# 《Not What You’ve Signed Up For: Compromising Real-World LLM-Integrated Applications》-2023
## 一、问题：问题场景、问题描述、问题挑战
### 1. 问题场景
当下检索增强、插件式LLM应用（Bing Chat、GitHub Copilot、Office Copilot等）大规模落地，模型会自动读取网页、代码库、邮件、本地文档等外部第三方数据作为上下文参与推理。现有提示注入研究全部聚焦**用户直接输入恶意指令**（直接提示注入），完全忽略第三方不可信外部数据可作为攻击载体；攻击者无需和应用交互，仅在公网网页、开源代码、邮件等公共资源植入隐藏恶意提示，当其他普通用户使用该LLM应用检索、读取这份资源时，恶意指令会被自动载入上下文，远程劫持模型行为，实现批量跨用户攻击，形成全新、大规模AI供应链安全漏洞，行业暂无系统性风险建模与验证。

### 2. 问题描述
本文提出**间接提示注入（Indirect Prompt Injection, IPI）**全新攻击范式：攻击者不直接向应用输入内容，而是将恶意提示预埋在公开可被LLM检索读取的外部数据中；任意普通用户触发应用加载该数据时，隐藏指令混入上下文，劫持模型执行攻击者预设恶意行为。论文建立完整IPI威胁分类体系，在Bing Chat、代码补全工具、自研仿真Agent多类真实系统完成PoC验证，证实可实现用户隐私窃取、钓鱼诈骗、恶意代码传播、远程控制、虚假信息散播、服务拒绝六大类高危攻击；同时证明现有对齐、输出过滤等安全机制难以防御此类远程隐性注入威胁。

### 3. 问题挑战
1. **攻击载体全新性**：传统注入依托用户输入框，IPI依托第三方检索数据，攻击入口完全不同，现有攻防研究无对应分析框架；
2. **隐蔽与规模化约束**：恶意提示可隐藏在网页注释、代码注释、编码文本内，单份污染资源可影响成千上万不知情用户，批量攻击风险极高；
3. **攻击链路复杂**：模型具备检索、读取文档、调用API、持久记忆、多轮对话能力，注入指令可跨会话持久生效、远程拉取更新载荷，攻击链路多阶段难以阻断；
4. **威胁多元化建模**：IPI可衍生信息窃取、欺诈、蠕虫式污染、远程后门、虚假信息、DoS多类攻击，需要统一分类评估；
5. **黑盒真实场景验证**：需要在商用闭源产品（Bing Chat）、代码工具、仿真Agent多环境复现攻击，验证现实危害性；
6. **防御缺失难题**：RLHF对齐、输出过滤、基础输入清洗仅针对用户输入，无法识别外部检索数据内隐藏指令，缺少有效防护思路。

> 对应基本要求：区分传统直接提示注入，聚焦检索增强LLM独有第三方数据漏洞，核心痛点是公网资源可预埋隐性指令、实现跨用户远程批量劫持，现有安全体系完全覆盖不到该攻击面。

## 二、现有工作及不足：现有工作核心思路、存在的问题及根本原因
### 1. 现有工作核心思路
1. 直接提示注入（Ignore Previous Prompt等）：恶意用户在对话输入框直接写入劫持指令，攻击发起者为当前会话用户，仅影响单条对话；
2. 越狱攻击(Jailbreak)：针对基座模型安全护栏，绕过内容过滤，依赖用户主动输入诱导文本；
3. 检索增强LLM研究：仅优化检索召回精度、减少幻觉，未考虑检索内容内含恶意指令的安全风险；
4. LLM插件/Agent安全：侧重API调用权限管控，忽略检索文本本身可作为“代码指令”劫持模型决策；
5. 传统Web注入（SQL/XSS）：输入可控，无跨会话、第三方资源预埋攻击的对应类比分析；
6. 模型对齐(RLHF/DPO)：仅约束用户直接提问输出内容，不区分上下文来源是否可信。

### 2. 存在的问题
1. 攻击场景局限：全部现有注入/越狱研究均限定攻击者为会话直接使用者，未发现第三方公共资源可作为攻击媒介；
2. 数据-指令边界认知缺失：现有研究默认检索内容仅为参考数据，未意识到LLM上下文无数据/指令隔离，文本均可被模型解读为执行命令；
3. 无标准化威胁分类：缺少间接注入衍生各类恶意行为的统一归类、评估框架；
4. 现实验证不足：多数提示注入仅在小型仿真模型测试，未在Bing Chat、Copilot等线上商用黑盒产品复现；
5. 防御方案片面：现有防护仅处理用户输入，不校验外部检索、读取的第三方文档内容，无法拦截IPI载荷。

### 3. 根本原因
过往LLM安全研究默认“只有用户输入属于不可信输入源”，未识别网页、代码、邮件等外部检索资源同样是高风险不可信上下文；忽略检索增强架构天然模糊「参考数据」与「执行指令」的边界，没有针对远程预埋、跨用户、持久化隐性注入的威胁建模与攻防分析。

> 对应基本要求：横向对比直接注入、越狱、检索优化、对齐相关文献，从「忽视第三方不可信检索源、未区分数据与指令边界、无IPI完整威胁体系」三点提炼底层研究空白。

## 三、方案：方案动机、方案整体思路、关键步骤、关键技术
### 1. 方案动机
现有提示注入仅能单会话本地攻击，无法实现远程、批量、跨用户劫持；检索增强LLM大规模普及但第三方数据安全完全空白。本文提出间接提示注入IPI攻击范式，构建完整攻击投递方式+威胁分类框架，在多款真实商用AI产品完成PoC验证，系统揭示远程预埋恶意指令带来全品类安全危害，并讨论现有防御体系局限性。

### 2. 方案整体思路
整体分为三大模块：IPI攻击投递手段分类、六类核心威胁建模、多平台PoC验证。
1. 投递手段：划分被动检索污染、主动推送污染、用户复制诱导、多阶段编码隐藏四类预埋载荷方式；
2. 威胁体系：类比传统网络安全，归纳信息窃取、诈骗、远程入侵、蠕虫传播、内容操纵、可用性破坏六大IPI衍生攻击；
3. 验证流程：搭建LangChain仿真Agent + 商用Bing Chat + GitHub Copilot三类靶标，分别复现各类攻击，测试载荷持久化、远程更新、编码隐藏等进阶攻击手段，总结现有防护失效原因。

### 3. 关键步骤
1. 梳理IPI四类载荷投递方案：
    - 被动投递：网页、开源代码库预埋隐藏提示，用户检索时自动读入上下文；
    - 主动投递：含恶意指令邮件推送给用户，AI助手自动读取解析；
    - 用户驱动诱导：诱导用户复制带隐藏载荷文本粘贴提问；
    - 隐藏多级载荷：基础短指令触发模型拉取远端完整恶意payload；
2. 构建六类标准化攻击威胁模型，明确每类攻击实现逻辑与危害；
3. 搭建两套实验环境：①基于GPT-4/LangChain可控制仿真Agent（含搜索、邮件、持久内存API）；②黑盒商用产品Bing Chat、GitHub Copilot；
4. 编写多类原生、Base64编码、注释隐藏型IPI载荷，批量测试攻击成功率；
5. 验证持久化、远程C2控制、多轮会话延续等高阶攻击效果；
6. 分析RLHF、输出过滤、简单输入清洗等现有手段对IPI的防御失效原因。

### 4. 关键技术
1. **数据-指令边界模糊攻击**：利用LLM上下文无来源可信区分机制，将恶意指令伪装成文档注释、代码注释、不可见字符混入参考素材；
2. **多阶段链式载荷**浅层隐藏指令触发模型主动访问攻击者服务器拉取完整攻击逻辑，规避长载荷易被检测问题；
3. 编码隐蔽载荷：Base64等编码封装恶意提示，普通文本过滤无法识别，模型可自主解码执行；
4. 持久化注入机制：诱导模型将恶意指令存入会话长期内存，跨轮次持续劫持行为；
5. 跨平台靶标验证：同时在可控仿真Agent与闭源商用黑盒产品完成PoC，证明攻击普适性；
6. 类比传统网络安全的威胁分类框架，实现IPI危害标准化归类，便于后续防御研究。

> 对应基本要求：动机填补检索增强LLM远程隐性注入安全空白，流程分为投递分类-威胁建模-多平台验证三段，每项技术分别解决载荷隐蔽、链式攻击、持久劫持、真实场景验证四大核心挑战。

## 四、实验：实验数据、对比方法、评价标准、参数设置、实验数据及分析
### 1. 实验数据与靶标
1. 仿真LLM Agent：基于LangChain搭建，集成搜索、网页读取、邮件读写、通讯录、持久KV内存API，基座选用text-davinci-003、GPT-4；
2. 商用黑盒靶标：Bing Chat（Edge侧边网页读取功能）、GitHub Copilot代码补全；
3. 攻击载荷：原生文本IPI、换行/注释隐藏载荷、Base64编码多级载荷；
4. 测试攻击类型：信息窃取、钓鱼诈骗、蠕虫邮件传播、远程C2后门、虚假信息篡改、DoS耗尽攻击。

### 2. 对比方法
1. 基线：传统**直接提示注入**（用户输入框写入劫持指令）；
2. 消融对照组：普通明文载荷 / 注释隐藏载荷 / Base64多级载荷；
3. 防御对照：原生RLHF对齐、基础输出关键词过滤、简单输入清洗。

### 3. 评价标准
1. 攻击成功率：加载污染素材后模型执行攻击者指定恶意逻辑的样本占比；
2. 隐蔽性：人工基础文本筛查能否识别载荷；
3. 持久化能力：重启对话、读取内存后是否再次触发劫持；
4. 跨平台通用性：仿真Agent/ Bing Chat / Copilot三类靶标是否均可攻破；
5. 防御逃逸率：开启现有安全机制后攻击仍生效比例。

### 4. 参数设置
1. 模型生成温度固定0保证可复现；
2. 载荷隐藏方式：HTML注释、代码行注释、零宽字符、Base64编码；
3. 多阶段攻击：浅层触发指令指向攻击者控制URL拉取完整payload；
4. Bing Chat使用网页本地HTML文件模拟公网污染页面，避免线上滥用；
5. 每组攻击重复多轮对话测试跨轮次持久效果。

### 5. 实验数据及分析
1. 核心攻击有效性：所有六类间接注入攻击在仿真Agent全部稳定生效；Bing Chat网页读取、Copilot代码注释场景攻击成功率极高，单份污染网页/代码可影响任意检索用户，实现批量攻击。
2. 载荷隐蔽消融：明文载荷易被人工识别；注释、不可见字符、Base64编码载荷几乎肉眼不可见，基础文本过滤完全无法检出。
3. 持久化与远程控制验证：注入指令可存入模型长期记忆，新会话读取内存自动重新劫持；模型可按指令周期性访问攻击者服务器拉取新攻击逻辑，形成持续AI后门。
4. 跨场景差异：代码类IPI在Copilot依托注释隐蔽性极强；网页IPI依托Edge侧边读取功能覆盖全部网页浏览用户；邮件型IP可借助AI邮件助手批量传播蠕虫式恶意指令。
5. 现有防御失效结论：单纯RLHF对齐、输出关键词过滤、仅清洗用户输入均无法拦截IPI，攻击载体来自第三方检索数据，现有防护完全不覆盖该输入源；仅靠事后输出拦截无法阻止模型主动发起API窃取、外联操作。
6. 现实安全危害：可批量诱导用户泄露隐私、自动发送钓鱼邮件、篡改检索摘要散播虚假信息、持续占用算力实现隐性DoS，覆盖个人隐私、企业算力、舆论安全多维度风险。
7. 研究局限：无法大规模公网预埋载荷做线上实测；未提出完整成熟防御方案，仅指出现有防护短板；多模态图片隐藏IPI仅理论提及，未充分实验验证。

> 对应基本要求：实验覆盖可控仿真Agent与主流商用闭源LLM应用，完整对比直接注入基线、多类隐蔽载荷；实验结果证实IPI具备远程、批量、持久化高危特性，现有对齐与过滤防御全部失效，清晰揭示检索增强架构底层安全缺陷。


# 《The Instruction Hierarchy: Training LLMs to Prioritize Privileged Instructions》-2024
## 一、问题：问题场景、问题描述、问题挑战
### 1. 问题场景
当前LLM驱动的智能Agent、检索助手、办公Copilot等应用普遍采用分层上下文输入结构：开发者固定系统提示(System)、用户输入、网页/代码等第三方工具返回内容三类文本共存。现有大模型无指令优先级区分机制，所有文本被模型同等解析，攻击者可在用户输入、检索网页等低可信内容中植入劫持指令，覆盖高权限系统规则，引发直接提示注入、间接提示注入、越狱、系统提示窃取四大高危漏洞；现有防御多为输入过滤、后置输出拦截，只能缓解无法从模型底层根治冲突指令覆盖问题，且普遍存在过度拒绝或泛化差缺陷。

### 2. 问题描述
本文提出**指令层级（Instruction Hierarchy）**底层对齐防御范式：为上下文四类文本划分固定权限优先级（系统消息最高>用户消息>模型输出>第三方工具返回最低），通过专用合成数据集微调LLM，训练模型天然遵循高权限指令、自动忽略低可信冲突指令。设计两套数据生成方案分别处理相容/冲突指令，在GPT-3.5完成微调验证；对训练时未见过的新型越狱、注入攻击具备零样本泛化能力，各类攻击鲁棒性最高提升63%，通用基础能力几乎无衰减，仅少量边界场景出现轻微过度拒绝。

### 3. 问题挑战
1. **权限分层建模空白**：现有LLM对齐不区分上下文来源可信度，无天然指令优先级逻辑，无法自动隔离第三方不可信内容；
2. **指令二元区分难题**：低权限内容分为相容无害指令、冲突恶意劫持指令，模型需要差异化处理（相容执行、冲突忽略），单一拒绝逻辑会严重损害基础问答能力；
3. **泛化性约束**：防御不能仅拟合训练集中已知攻击，需对训练未覆盖新型注入、越狱手段具备抵抗能力；
4. **效用-安全权衡**：强化指令层级不能大幅降低通用问答、摘要、推理等基准任务效果；
5. **多攻击全覆盖要求**：一套微调框架需要同时抵御直接注入、检索间接注入、系统提示窃取、越狱四类主流LLM攻击；
6. **过度拒绝抑制**：模型不能把外观相似的良性低权限指令误判为攻击、拒绝正常用户需求。

> 对应基本要求：聚焦Agent检索类应用上下文多源混合独有安全缺陷，区别输入过滤、后置修复类防御，从模型预对齐底层解决指令覆盖根源问题，清晰点明“无权限分层”核心底层漏洞。

## 二、现有工作及不足：现有工作核心思路、存在的问题及根本原因
### 1. 现有工作核心思路
1. 提示注入攻击类研究（HOUYI、间接提示注入IPI）：仅挖掘攻击实现方式，未提供模型原生根治防御方案；
2. 输入/输出过滤防御：部署前后端文本检测，拦截明显劫持句式，依赖特征匹配，新型攻击极易绕过；
3. 结构化输入隔离（StruQ）：通过特殊标记分隔数据与指令，依赖应用层格式化，模型底层仍无优先级认知；
4. 单一层对齐微调：仅区分系统与用户文本，无法处理网页/工具第三方低可信内容，无分层权限体系；
5. RLHF基础对齐：仅约束模型输出有害内容，无法解决上下文内低权限指令覆盖高权限系统规则的逻辑漏洞；
6. 越狱专项防御：针对安全护栏绕过做数据增强，不解决指令层级冲突底层根源。

### 2. 存在的问题
1. 防御治标不治本：过滤、格式化隔离均属于应用层补救，模型内部仍同等看待全部上下文文本；
2. 分层粒度不足：现有对齐仅二元划分系统/用户，忽略网页、API返回等最低可信度第三方数据源；
3. 处理逻辑单一：要么全部拒绝低权限内容，要么全部执行，无法区分相容/冲突指令，造成严重能力衰减；
4. 泛化能力薄弱：基于已知攻击样本训练，全新变种注入、越狱手段会快速失效；
5. 无法统一覆盖多类威胁：现有方案只能针对性防御单一攻击（仅越狱/仅注入），缺少一体化防御框架。

### 3. 根本原因
过往LLM安全对齐研究仅关注输出内容合规性，未类比操作系统内核/用户权限思想，**未对多来源上下文建立层级信任体系**；没有区分低权限指令“相容无害”“冲突恶意”两种场景的差异化训练范式，仅靠表层过滤无法根除低可信内容劫持系统指令的底层漏洞。

> 对应基本要求：横向对比攻击研究、应用层过滤、单层对齐、基础RLHF四类文献，从“缺少多层权限底层对齐、无二元指令区分训练、泛化性差”三点提炼底层研究空白。

## 三、方案：方案动机、方案整体思路、关键步骤、关键技术
### 1. 方案动机
现有防御依赖应用层过滤，无法从模型底层解决低可信文本覆盖系统指令的核心漏洞，且大多泛化能力弱、容易过度拒绝。本文借鉴操作系统权限分级思想，提出四级指令层级体系，设计相容/冲突双模式合成微调数据，让模型原生优先遵循高权限系统指令，对已知、未知注入越狱攻击均具备强鲁棒性，同时最大程度保留原有通用能力。

### 2. 方案整体思路
整体分为三层核心模块：指令权限层级定义、双分支训练数据生成、SFT+RLHF联合微调。
1. 权限层级定义：固定四级优先级，System(最高) > User > 多媒体内容 > 工具/网页检索文本(最低)；
2. 数据生成分支：
    - 相容指令合成：拆分复合需求分散到低层级上下文，训练模型正常执行不冲突辅助指令；
    - 冲突指令遗忘：各类注入、越狱、窃取攻击放入低层级文本，训练模型完全忽略冲突内容；
3. 微调流程：混合通用基座数据+层级专项数据完成监督微调，搭配RLHF优化拒绝边界；
4. 多维度评测：同时测试已知攻击鲁棒性、零样本未知攻击泛化、通用任务精度、过度拒绝率。

### 3. 关键步骤
1. 标准化上下文层级标记：训练/推理全程用特殊标识区分四类来源文本，建立模型层级认知；
2. 相容样本构造：将完整用户需求拆分为主系统任务+分散低层级辅助描述，生成正常响应作为真值；
3. 冲突样本构造：红队LLM批量生成直接注入、间接网页注入、系统提示窃取、越狱四类恶意载荷，放置最低权限层级，真值为无视攻击的标准输出；
4. 混合数据集构建：通用基准数据+分层专项数据按比例混合，平衡安全与基础能力；
5. SFT+RLHF双阶段微调：先监督学习层级行为，再强化学习优化拒绝边界，降低过度拒绝；
6. 多维度消融评测：对比仅系统提示约束、无层级基线模型，验证层级微调增益。

### 4. 关键技术
1. **四级指令权限分层体系**：类比OS权限隔离，从模型底层建立上下文信任优先级，覆盖检索、API等第三方输入场景；
2. 双分支数据生成机制：相容分支保证正常辅助指令可执行，冲突分支训练自动忽略劫持，解决安全-能力权衡矛盾；
3. 红队自动对抗样本生成：利用LLM批量生成各类新型攻击载荷，扩充训练集多样性；
4. 零样本泛化对齐：训练不引入越狱、工具注入样本，模型仍可抵御该类未知攻击；
5. 双层微调优化（SFT+RLHF）：监督学习建立层级逻辑，强化学习精细调节拒绝阈值，抑制过度拒绝问题；
6. 分层基线对照：区分“仅系统提示文字约束”与“模型底层层级微调”两种方案，证明微调效果远优于单纯prompt提示。

> 对应基本要求：动机解决表层防御治标不治本痛点，流程分为层级定义-数据生成-双阶段微调三段，每项技术分别解决权限建模、指令二元区分、未知攻击泛化、过度拒绝四大核心挑战。

## 四、实验：实验数据、对比方法、评价标准、参数设置、实验数据及分析
### 1. 实验数据与模型
1. 基础模型：GPT-3.5 Turbo；
2. 训练数据集：通用语言基准（TriviaQA/LAMBADA）+分层专项合成数据集（相容/冲突两类样本）；
3. 攻击评测集：
    已知攻击：Toyer注入数据集、网页间接注入、系统提示窃取；
    零样本泛化：TensorTrust劫持、Gandalf密码窃取、各类越狱数据集；
4. 过度拒绝评测集：外观类似攻击的良性边界指令样本。

### 2. 对比方法
1. 基线模型：仅通用数据微调，无指令层级训练；
2. 简单提示基线：仅在系统提示文字中告知模型区分优先级，不做专项微调；
3. 消融对照组：仅相容数据训练、仅冲突数据训练、SFT无RLHF优化。

### 3. 评价标准
1. 攻击鲁棒性（越高越好）：模型不执行恶意指令的样本占比；
2. 通用任务精度：LAMBADA、TriviaQA等标准基准得分；
3. 过度拒绝率（越低越好）：良性低权限指令被模型错误拒绝的比例；
4. 泛化鲁棒性：训练未见过的新型攻击防御成功率。

### 4. 参数设置
1. 微调框架：SFT监督微调 + RLHF强化微调两阶段；
2. 层级文本使用专属分隔符区分四类上下文；
3. 专项分层数据与通用数据混合配比均衡；
4. 红队LLM批量生成各类劫持、越狱、窃取攻击样本；
5. 评测使用GPT-4作为裁判自动打分，消除人工主观偏差。

### 5. 实验数据及分析
1. 已知攻击大幅提升鲁棒性：相比普通基线，系统提示窃取防御鲁棒性提升63%，各类直接/间接注入防御指标均提升15~30个百分点；仅靠文字提示层级约束增益极低，底层微调效果碾压单纯prompt方案。
2. 零样本泛化能力突出：训练集未包含越狱、工具注入、密码窃取样本，对应攻击鲁棒性仍提升30%以上，证明模型真正学到层级逻辑，而非拟合固定攻击句式。
3. 通用能力几乎无损：TriviaQA、LAMBADA等基准指标与基线模型差距极小，分层微调不会损害模型基础理解、生成能力。
4. 过度拒绝可控：大部分良性相容指令遵从率接近基线；仅少数高度相似攻击的边界样本出现轻微拒绝衰减，可通过扩大相容样本集进一步优化。
5. 消融实验结论：相容、冲突两类样本缺一不可；仅用冲突样本会造成严重正常指令拒绝，仅相容样本无法抵御劫持攻击；RLHF阶段可显著降低过度拒绝比例。
6. 方案局限：当前层级规则默认网页/工具内容全部为低风险不可信，无法处理第三方来源的合法关键指令；仅覆盖文本模态，多模态图片隐式注入无法防御；极端复合多层嵌套劫持攻击仍存在少量逃逸案例。

> 对应基本要求：实验覆盖已知+零样本未知多类攻击、通用能力与过度拒绝双向指标，完整对比基线与简单prompt方案；消融实验验证双分支数据、RLHF优化的必要性，实验结论充分证明指令层级底层对齐是更通用、长效的提示注入防御方案。



# 《AgentDojo: A Dynamic Environment to Evaluate Prompt Injection Attacks and Defenses》-2024
## 一、问题：问题场景、问题描述、问题挑战
### 1. 问题场景
当前LLM智能Agent广泛接入邮件、银行、Slack、旅行预订等外部工具，模型读取第三方不可信返回文本时极易遭受间接提示注入（IPI）攻击，可造成数据泄露、恶意转账、批量钓鱼等高危害后果。但现有评测基准存在明显短板：大多为静态单轮文本测试，无法模拟多轮工具调用、有状态业务环境；依赖LLM充当虚拟环境裁判易被攻击样本劫持评测结果；缺少统一、可扩展的动态沙箱，无法标准化量化「任务可用性」与「安全抗注入能力」双向指标，攻防研究缺乏公平统一对比平台。

### 2. 问题描述
本文提出AgentDojo动态可扩展Agent评测沙箱框架，构建四类真实有状态业务仿真环境（办公、Slack、银行、旅行），内置74类工具、97项正常用户任务、629组安全攻击用例。框架不依赖大模型做裁判，采用确定性代码逻辑判定任务完成度与攻击成功率；支持自定义攻击载荷、防御流水线、Agent架构，可横向对比开源/闭源主流大模型，定量衡量**任务可用性**与**提示注入攻击成功率**权衡关系。实验证实主流商用大模型均存在明显注入漏洞，现有防御方案均无法做到安全与性能两全，为Agent安全攻防提供标准化动态评测底座。

### 3. 问题挑战
1. **环境仿真约束**：Agent为多轮有状态交互，静态单轮数据集无法复现工具链式调用、环境数据变更等真实业务流程；
2. **评测公平性难题**：传统基准使用LLM判定任务结果，恶意注入文本可劫持裁判模型，造成评测失真；
3. **双向指标量化**：评测需同时兼顾模型正常业务能力（可用性）与抗注入安全能力，缺少统一标准化判定逻辑；
4. **动态扩展需求**：攻防手段持续迭代，静态固定测试集无法适配新型自适应攻击、全新防御策略；
5. **多场景全覆盖**：需覆盖邮件、金融、社交、出行等高敏感垂直场景，统一工具调用范式；
6. **模型兼容约束**：评测框架需无缝适配GPT、Claude、Gemini、Llama等开源/闭源工具调用模型。

> 对应基本要求：聚焦工具调用式LLM Agent独有多轮有状态业务场景，区别纯文本静态提示注入基准，核心痛点是现有评测静态、裁判不可信、无统一效用-安全量化体系。

## 二、现有工作及不足：现有工作核心思路、存在的问题及根本原因
### 1. 现有工作核心思路
1. 纯文本提示注入基准（TensorTrust、Gandalf等）：仅单轮问答，无工具调用、环境状态变更，仅测试文本劫持；
2. Agent静态评测集（InjecAgent、AgentBench）：提供固定工具调用样本，无动态环境，依靠LLM自动打分；
3. 工具仿真基准ToolEmu：使用大模型模拟工具返回结果，评测逻辑易被注入载荷污染；
4. 单类攻防专项研究：仅针对某一种注入/防御手段做小规模验证，无横向大规模统一对比；
5. 隔离式防御研究（工具过滤、分隔符、指令层级）：缺少标准化动态Agent场景下量化验证平台。

### 2. 存在的问题
1. 仿真能力薄弱：全部现有基准为静态数据集，无法模拟多轮工具交互、环境数据持久变更的真实Agent流程；
2. 评测不可靠：依赖LLM充当环境/裁判，恶意注入文本会干扰打分逻辑，实验结果失真；
3. 指标单一：仅统计攻击成功率，未同步量化模型正常业务完成率，无法评估安全防护带来的性能损耗；
4. 不可扩展：测试用例、攻击、防御固定，难以迭代适配自适应新型注入攻击；
5. 场景覆盖有限：缺少金融、邮件等高敏感真实业务仿真，攻防实验贴近实验室、脱离产业风险场景。

### 3. 根本原因
过往Agent安全评测未意识到**工具调用、有状态环境是间接提示注入核心载体**，且普遍采用LLM作为不可信评测裁判；未设计确定性代码判定的动态沙箱架构，缺失同时衡量任务可用性与抗注入能力的标准化双向评测体系。

> 对应基本要求：横向对比纯文本注入、静态Agent、LLM仿真三类基准，从「静态无状态、裁判不可信、无双向量化、不可扩展」四点提炼底层研究空白。

## 三、方案：方案动机、方案整体思路、关键步骤、关键技术

现有Agent安全评测静态、评测结果易被劫持，无法统一量化安全与业务性能。本文设计AgentDojo动态沙箱，搭建四类确定性业务仿真环境，使用代码硬判定任务完成度与攻击成效，支持自定义攻防组件，提供可迭代标准化评测平台，统一衡量各类Agent、攻击、防御的效用-安全权衡。

4. 评测层：纯代码布尔函数判定可用性与攻击成功率，输出三类核心指标完成横向对比。

### 3. 关键步骤
1. 搭建确定性业务仿真环境：定义环境可变状态对象，实现74类标准化工具调用接口；

### 4. 关键技术
1. **确定性代码评测机制**：抛弃LLM裁判，通过环境状态前后变化、工具调用序列硬编码判定任务/攻击是否成功，杜绝评测劫持；
2. **多领域有状态动态沙箱**：仿真金融、社交等高敏感业务，支持多轮工具链式调用、数据持久变更；
3. 攻防插件化扩展架构：攻击、防御、Agent完全解耦，支持自适应迭代攻击、新型防御快速接入；
4. 双向权衡指标体系：同步统计原生可用性、受攻击可用性、目标攻击成功率，直观展现安全防护的性能代价；
5. 跨模型统一推理接口：兼容GPT/Claude/Gemini/Llama等开源、闭源工具调用基座，统一输入输出格式。

> 对应基本要求：动机解决现有基准评测失真、静态脱离真实Agent场景痛点，流程分为环境构建-任务生成-组件封装-批量评测四段，每项技术分别解决评测可信、动态仿真、可扩展、双向量化四大核心挑战。

7. 方案局限：当前仅覆盖文本注入，未拓展多模态图像隐式注入；缺少长上下文、多轮持久化注入场景深度测试；未内置自动对抗攻击生成模块。

> 对应基本要求：实验覆盖全系列主流开源/闭源大模型、四大高敏感业务场景、四类攻击五类防御，完整消融攻击句式、防御机制、业务环境；实验结论证实现有Agent防护均存在性能损耗，验证AgentDojo动态沙箱是可靠标准化评测平台。

# 《The Task Shield: Enforcing Task Alignment to Defend Against Indirect Prompt Injection》-2025
## 一、问题：问题场景、问题描述、问题挑战
### 1. 问题场景
工具增强型LLM Agent（办公、银行、Slack、旅行助手）广泛落地，Agent会读取网页、邮件、文档等第三方不可信外部数据，极易遭受**间接提示注入（IPI）**：攻击者将恶意指令嵌入网页/文档等工具返回内容，模型读取后会绕过原有任务，执行泄露隐私、恶意转账、批量钓鱼等高危操作。现有防御（分隔符、提示三明治、工具过滤、注入分类检测）存在明显效用-安全权衡缺陷：要么大幅降低模型正常任务完成率，要么无法有效拦截各类隐蔽注入载荷；现有防御仅从“识别有害文本”角度设计，未抓住IPI底层根源——模型执行脱离用户原始任务目标，缺少从任务对齐角度的底层防御思路。

### 2. 问题描述
本文提出**任务对齐（Task Alignment）**全新安全范式，颠覆传统“识别有害内容”防御逻辑，核心思想：仅允许对用户目标有贡献的指令/工具调用被执行，所有偏离用户任务的注入指令自动屏蔽。基于该思想设计**Task Shield**运行时防御框架，包含指令提取、对齐打分、反馈干预三大核心模块，在对话全链路（用户输入、Agent推理、工具返回文本）实时校验每条指令与用户目标的相关性；在AgentDojo标准基准上验证，针对最强Important注入攻击，GPT-4o整体攻击成功率仅2.07%，同时维持69.79%高任务可用性，全面优于分隔符、检测类、工具过滤等基线防御，适配多模型、四类真实业务场景。

### 3. 问题挑战
1. **防御思路范式空白**：现有防御均检测“有害关键词/句式”，无法区分“看似无害但偏离用户目标”的隐蔽注入指令，缺少以用户任务为核心的校验逻辑；
2. **多链路全量校验约束**：注入可隐藏在工具返回长文本、Agent推理步骤、工具调用参数中，防御需覆盖对话四层消息（系统/用户/助手/工具），不能存在校验盲区；
3. **效用-安全平衡难题**：校验机制不能误拦截合法中间步骤（如查资料、查联系人等辅助工具调用），需区分“中间有用指令”与“恶意偏离指令”；
4. **多类型注入泛化**：需抵御Important、Ignore、InjecAgent三类主流间接注入，兼顾短隐藏指令、长嵌套恶意文本；
5. **轻量化落地约束**：提供可拆分部署方案（仅输入校验/全链路校验），适配算力有限线上Agent服务；
6. **模型通用性**：防御不绑定单一基座，GPT3.5/4o/4o-mini均可稳定部署，强弱模型下均保持安全增益。

> 对应基本要求：聚焦工具Agent间接注入独有安全缺陷，区别传统关键词、分隔符类表层防御，核心创新是从“任务对齐”底层逻辑解决注入根源，而非简单识别有害文本。

## 二、现有工作及不足：现有工作核心思路、存在的问题、根本原因
### 1. 现有工作核心思路
1. **标记分隔类防御（Delimit/Spotlight）**：用特殊符号隔离工具输出，提示模型忽略分隔内指令，依赖模型遵守格式约束，复杂嵌套注入极易绕过；
2. **提示强化（Prompt Sandwich）**：重复用户原始任务强化优先级，面对高权重Important类注入防御效果大幅衰减；
3. **注入检测器（PI Detector）**：训练分类模型识别恶意文本，误报率极高，大量合法工具调用被拦截，任务可用性暴跌；
4. **工具过滤（Tool Filter）**：仅开放用户任务所需工具，同一任务内恶意参数无法拦截（如转账给攻击者）；
5. **层级对齐微调（Instruction Hierarchy）**：训练时赋予消息权限优先级，属于训练阶段方案，无法适配第三方闭源API模型；
6. **Agent评测基准（AgentDojo/InjecAgent）**：仅提供攻防测试环境，未给出针对性防御解决方案。

### 2. 存在的问题
1. **防御视角局限**：全部基线聚焦“识别有害内容”，忽略注入本质是行为脱离用户目标，隐蔽、良性包装的恶意指令无法检出；
2. **校验链路残缺**：大多仅校验工具返回文本，未拦截Agent生成的恶意工具调用，存在攻击逃逸漏洞；
3. **权衡失衡**：强安全方案（检测器）严重损害正常任务精度，保效用方案（三明治）抗注入能力弱；
4. **部署限制**：训练型防御无法用于OpenAI等不可微调闭源大模型；
5. **区分能力不足**：无法区分“合法中间辅助操作”和“恶意偏离指令”，易产生大量误拦截。

### 3. 根本原因
过往间接注入防御未抓住攻击核心机理：IPI成功的本质是模型执行**与用户目标无关的外部指令**；仅做内容过滤/格式约束，未建立“指令-用户任务贡献度”的量化校验机制，缺少运行时全链路任务对齐监控体系。

> 对应基本要求：横向对比分隔、检测、工具限制、训练对齐四类防御，从“防御视角错误、无任务贡献量化、校验链路不全”三点提炼底层研究空白。

## 三、方案：方案动机、整体思路、关键步骤、关键技术
### 1. 方案动机
现有表层防御无法兼顾安全性与任务可用性，且难以应对包装成良性的隐蔽间接注入。本文提出任务对齐核心安全准则，设计运行时无训练依赖的Task Shield校验框架，全链路监控所有指令与用户目标相关性，自动屏蔽偏离任务的恶意指令，同时保留合法中间工具调用，实现安全与效用帕累托最优。

### 2. 方案整体思路
整体为三段式实时校验流水线，嵌入Agent对话完整链路：
1. **指令提取模块**：从用户消息、助手回复、工具返回文本中抽取全部可执行动作指令，持久存储用户全部原始任务作为校验基准；
2. **对齐打分模块**：采用模糊贡献度打分机制，量化每条外部指令对用户任务的贡献（0=完全无关，1=直接完成任务，中间值为合法中间步骤）；
3. **反馈干预模块**：贡献度为0的判定为恶意注入，生成标准化反馈回传给Agent，强制放弃该指令，仅保留有效操作；
支持两种轻量化拆分部署：仅校验工具输入（Input Shield，低延迟）、全链路完整Task Shield（最高防护强度）。

### 3. 关键步骤
1. 用户消息处理：提取并更新全局用户任务集合$T_u$，作为后续所有对齐校验的基准；
2. 助手消息/工具调用校验：抽取Agent计划执行的动作，逐条计算贡献得分，0分指令直接拦截，生成提醒反馈；
3. 工具返回文本校验：解析网页/邮件等第三方内容内隐藏指令，无关恶意指令全部屏蔽；
4. 多轮对话循环校验：每一轮消息均走提取-打分-干预流程，持续锁定用户原始目标；
5. 消融部署测试：对比单输入校验、全链路校验、无任务提醒三种变体，选择算力-安全平衡方案；
6. 多攻击/多模型批量评测：在AgentDojo四大业务套件对比全部基线防御。

### 4. 关键技术
1. **任务对齐形式化定义**：提出ContributesTo贡献度二元关系，从数学上区分合法中间步骤与恶意偏离指令，突破单纯有害文本识别局限；
2. **模糊0-1贡献打分机制**：放弃粗暴二分类，允许中间辅助指令获得非零分数，大幅降低误拦截率；
3. **全四层消息覆盖校验**：用户/助手/工具/系统消息统一解析校验，消除注入逃逸链路；
4. **分层可拆分部署架构**：Input轻量模式、完整Task Shield双版本，适配不同算力业务；
5. **对话上下文感知打分**：结合全部历史用户任务判断指令价值，单条文本脱离上下文不会误判；
6. **无训练运行时方案**：无需微调基座，兼容GPT系列闭源API，线上业务零改造接入。

> 对应基本要求：动机解决传统防御效用安全失衡痛点，流程为提取-打分-干预三段闭环，每项技术分别解决隐蔽注入识别、合法指令区分、全链路拦截、轻量化落地四大挑战。

## 四、实验：实验数据、对比方法、评价标准、参数设置、实验数据分析
### 1. 实验数据与评测环境
1. 评测基准：AgentDojo完整四大套件（Travel旅行、Workspace办公、Banking金融、Slack社交）；
2. 基座模型：GPT-4o、GPT-4o-mini、GPT-3.5-turbo；
3. 攻击载荷：Important Instructions（最强高危注入）、Ignore Previous、InjecAgent三类主流间接注入；
4. 对比防御：无防护、分隔符、Prompt三明治、PI注入检测器、工具过滤。

### 2. 对比方法
1. 空白基线：无任何防御原生Agent；
2. 传统表层防御：Delimit分隔、Repeat三明治、PI分类检测器、Tool工具过滤；
3. Task Shield消融变体：仅Input校验、仅Action工具校验、移除任务提醒模块、完整全链路版本；
4. 不同强度校验模型消融：3.5/4o-mini/4o作为打分器对比开销与防护效果。

### 3. 评价标准
1. Clean Utility（CU，越高越好）：无攻击时正常任务完成率；
2. Utility under Attack（U，越高越好）：存在注入攻击下任务完成率；
3. ASR攻击成功率（越低越好）：注入指令成功执行的样本占比；
4. 辅助指标：单轮对话延迟、推理算力开销。

### 4. 参数设置
1. 贡献度判定阈值：0分即为未对齐恶意指令；
2. 打分模型温度固定0，保证打分确定性；
3. 消融实验拆分：仅工具输入校验、仅工具调用拦截、无用户目标提醒；
4. 每类任务重复多轮，统计均值用于帕累托效用-安全曲线绘制。

### 5. 实验数据及分析
1. **主防御效果**
最强Important注入下，无防护GPT-4o整体ASR高达47.69%；完整Task Shield将ASR压至2.07%，同时维持69.79%任务可用性，所有基线均无法同时实现低ASR+高效用：检测器ASR极低但任务精度暴跌，三明治、分隔符安全效果差。
2. **帕累托最优验证**
四类业务场景效用-安全散点图中，Task Shield稳定位于右下最优帕累托区域，同等攻击成功率下任务完成度显著高于所有对比防御。
3. **消融实验核心结论**
- Input Shield（仅校验工具返回）性价比最高，延迟仅为完整框架1/3，ASR可降至4.76%，适合低算力服务；
- Action工具调用拦截作为兜底防护，防止恶意动作执行；
- 移除用户目标提醒模块后任务可用性大幅下滑，多轮对话极易偏离原始需求；
4. **模型泛化能力**
GPT-4o-mini、GPT3.5作为打分器依然有效，仅小幅提升AS；原生对齐4o-mini无防护ASR更低，但Task Shield仍能进一步压制注入风险；
5. **场景差异化表现**
Slack网页读取场景注入原生成功率最高，Task抑制效果最明显；金融套件因操作权限敏感，各类防御均有小幅效用损失，但本文方案衰减幅度最小；
6. **方案局限**
依赖额外LLM打分器带来推理延迟；弱打分模型存在少量漏检；仅在GPT系列完成验证，未测试开源LLaMA/Mistral；无法抵御多模态图片嵌入间接注入。

> 对应基本要求：实验覆盖四大高风险业务场景、三类主流注入、多规格GPT模型，完整消融轻量化部署变体与打分模型；帕累托曲线、多维度指标完整证明任务对齐思路的攻防权衡优势，同时客观给出方案落地局限性。

# 《Memory Injection Attacks on LLM Agents via Query-Only Interaction（MINJA）》-2025
## 一、问题：问题场景、问题描述、问题挑战
### 1. 问题场景
当前大量LLM智能Agent（医疗EHR、网页购物RAP、通用问答Agent）采用**长期记忆库+检索上下文学习**架构：交互记录存入记忆，新用户查询时召回相似历史对话作为示例引导推理；主流产品（ChatGPT记忆、医疗AI、电商助手）采用**全局共享记忆**，所有用户交互数据统一存储。现有记忆投毒攻击（AgentPoison）均假设攻击者拥有直接写入/篡改记忆的系统权限，现实中普通外部用户无后台访问权，仅能提交普通查询交互，该强假设大幅降低攻击现实威胁；业界缺少仅通过正常对话即可污染共享记忆、实现跨用户持久劫持的攻击范式，记忆模块安全存在重大未覆盖漏洞。

### 2. 问题描述
本文提出**MINJA纯查询式记忆注入攻击**，攻击者无需后台权限，仅通过正常用户接口提交定制查询，就能自主诱导Agent生成并存储恶意交互记录至共享记忆；核心逻辑是在查询中附加引导提示，生成「过渡桥接推理步骤」打通无害用户词与恶意目标实体的语义关联，再通过渐进缩短策略逐步移除引导提示，最终留存外观完全正常、但暗藏定向劫持逻辑的污染记忆。任意后续受害者提交含目标关键词的查询时，Agent会召回污染记录，执行攻击者预设恶意行为（医疗篡改患者数据、电商强制跳转商品、问答篡改答案）；实验在医疗、电商、通用三类Agent验证，平均注入成功率ISR=98.2%，攻击触发ASR=76.8%，且现有检测、隔离防御均难以完全阻断。



### 3. 问题挑战
1. **权限约束难题**：攻击者无记忆库读写权限，只能依靠Agent自主生成、保存污染记录，无法直接植入恶意样本；
2. **语义鸿沟障碍**：受害者关键词（如患者A）与攻击者目标实体（患者B）无天然逻辑，普通查询无法诱导模型自动跳转目标推理；
3. **隐蔽性要求**：带引导提示的查询会被人工/规则筛查，必须逐步剥离提示，生成肉眼、检索嵌入均与正常记录无差别的污染样本；
4. **跨场景通用性**：攻击需要适配医疗数据库、网页工具、通用CoT问答三类完全不同的Agent推理逻辑；
5. **防御逃逸**：嵌入聚类、输入关键词检测、分层记忆隔离等现有防护手段难以区分良性与污染记忆；
6. **效用平衡约束**：批量投毒不能破坏Agent正常业务能力，仅定向劫持含指定受害者关键词的查询。

> 对应基本要求：区别AgentPoison等需要后台权限的记忆投毒，聚焦**普通用户仅对话即可污染全局共享记忆**全新现实威胁，核心痛点是现有攻击假设脱离线上产品权限模型，缺少低门槛持久跨用户劫持攻击。

## 二、现有工作及不足：现有工作核心思路、存在的问题、根本原因
### 1. 现有工作核心思路
1. **Agent记忆后门（AgentPoison）**：攻击者直接后台写入含触发器的污染记忆记录，受害者查询匹配触发器即触发恶意推理；依赖系统权限，普通用户无法实施；
2. **间接提示注入IPI**：污染网页/工具返回文本，仅单次对话生效，无法存入长期记忆，无跨会话持久劫持能力；
3. **RAG知识投毒（PoisonedRAG）**：污染外部知识库文档，不针对Agent交互记忆存储机制；
4. **推理越狱/提示劫持（Pandora）**：仅单轮对话劫持模型输出，不修改长期记忆，攻击无留存性；
5. **Agent记忆安全研究**：仅做记忆隔离、嵌入清洗防御，未建模纯前端查询式投毒威胁。

### 2. 存在的问题
1. **攻击门槛过高**：主流记忆投毒均假设攻击者拥有后台修改权限，不符合SaaS、共享Agent普通用户使用场景；
2. **攻击无持久性**：IPI、单轮越狱仅临时劫持本轮对话，无法污染长期记忆，批量影响多名受害者；
3. **语义连通方案缺失**：没有桥接推理机制，无法让模型自主建立“受害者实体→恶意目标”永久关联；
4. **隐蔽性不足**：现有污染样本自带明显特殊触发器，极易被关键词、嵌入聚类检测拦截；
5. **场景单一**：缺少医疗、电商高风险垂直Agent的系统性攻击验证。

### 3. 根本原因
过往Agent记忆安全研究默认**记忆写入是系统特权操作**，忽略Agent“用户交互后自动存储对话”原生机制；未意识到可通过分步引导、渐进剥离提示的方式，让模型自主生成、留存语义劫持记录，也未挖掘“桥接推理步骤”打通无关实体逻辑的核心攻击路径。

## 三、方案：方案动机、方案整体思路、关键步骤、关键技术
### 1. 方案动机
现有记忆投毒攻击依赖后台权限，现实可用性极低；普通用户仅能提交查询的场景下，缺少可持久、跨用户劫持记忆攻击。本文设计MINJA攻击，仅通过前端对话交互诱导Agent自主生成污染记忆，依靠桥接推理+渐进缩短策略实现高隐蔽、高成功率投毒，覆盖医疗、电商、通用问答多类Agent，揭示共享记忆架构原生安全漏洞。

### 2. 方案整体思路
攻击分为两大阶段：
1. **渐进缩短PSS迭代注入**：初始查询附带完整引导提示，诱导Agent生成「桥接推理+目标恶意步骤」并保存；每轮迭代删减一段引导提示，重复交互存储多份逐步淡化提示的污染记录，最终生成无任何异常提示、仅保留桥接逻辑的干净外观污染样本；
2. **受害者劫持阶段**：其他用户提交含受害者关键词正常查询，记忆检索召回多条污染记录，上下文示例诱导模型自动执行攻击者预设恶意推理，完成定向篡改、泄露、跳转等攻击。



### 3. 关键步骤
1. **构造攻击元组**：选定受害者实体v、恶意目标实体t，设计适配当前Agent的桥接逻辑（如患者A数据存于患者B下）；
2. **构造初始带提示查询**：在正常含v的查询后附加完整引导提示，强制模型输出v→t桥接推理；
3. **渐进缩短迭代**：每轮删减一段引导文本，提交新查询，Agent生成简化版污染记录并存入共享记忆；
4. **多轮迭代沉淀**：重复缩短直至查询仅保留正常受害者问句、无任何异常提示，生成高度隐蔽污染记忆；
5. **受害者测试**：使用全新含v正常查询访问Agent，召回多条污染记录，统计恶意推理触发率ASR；
6. **多变量消融**：嵌入模型、良性数据密度、前置污染、各类防御下验证攻击稳定性。

### 4. 关键技术
1. **桥接推理步骤设计**：构造逻辑过渡文本，在无外部篡改前提下，让模型自主建立受害者实体到恶意目标的永久语义关联；
2. **渐进缩短策略PSS**：分步剥离攻击引导提示，最终污染记录外观与正常交互完全一致，规避关键词检测；
3. **纯查询无权限投毒范式**：全程仅使用普通用户查询接口，无需任何后台读写权限，贴合线上SaaS真实攻击路径；
4. **多领域适配攻击模板**：分别针对医疗ID/药品、电商商品、学术术语定制桥接逻辑，跨Agent通用；
5. **多轮记忆叠加放大**：迭代生成多条相似度极高的污染记录，大幅提升受害者查询时的召回概率，稳定拉高ASR。

> 对应基本要求：动机解决现有投毒权限过高、无法落地的痛点，流程分为迭代注入、受害者劫持两段，每项技术分别解决语义打通、隐蔽生成、低门槛攻击三大核心挑战。

## 四、实验：实验数据、对比方法、评价标准、参数设置、实验数据及分析
### 1. 实验数据与Agent环境
1. 三类测试Agent：
    - EHRAgent（医疗电子病历，数据集MIMIC-III/eICU）；
    - RAP（电商网页购物，Webshop数据集）；
    - 通用CoT问答Agent（MMLU多学科数据集）；
2. 基座LLM：GPT-4 / GPT-4o，补充DeepSeek-R1、Llama2消融；
3. 受害者-目标元组：患者ID、药品、电商商品、学科术语四大类9组配对；
4. 记忆检索：all-MiniLM、ada-002、DPR、BGE等多款嵌入模型，支持高斯噪声消融。

### 2. 对比/消融实验组
1. 基准对比：AgentPoison（后台直写记忆）；
2. 消融变量：有无PSS渐进缩短、不同嵌入检索模型、记忆良性样本密度、记忆已存在前置污染；
3. 防御对照：提示关键词检测、嵌入聚类清洗、用户记忆隔离、时序衰减防护。

### 3. 评价标准
1. IS（注入成功率）：攻击者提交查询后，成功生成污染记忆的比例（越高攻击越易实施）；
2. ASR（攻击触发率）：受害者正常查询下，模型执行恶意推理占比（越高威胁越大）；
3. UD（效用衰减）：投毒后模型正常业务任务准确率下降幅度（越小隐蔽性越强）。

### 4. 参数设置
1. PSS迭代轮次：医疗5轮、电商5轮、问答5轮；
2. 污染查询数量：每组受害者10~15条；
3. 记忆检索召回条数：EHRAgent4条、RAP3条、QA5条；
4. 嵌入噪声消融σ=0.01，良性样本梯度25/50/75/100条。

### 5. 实验数据及分析
1. **核心攻击有效性**
    全场景平均注入成功率ISR=98.2%，平均攻击触发ASR=76.8%；电商RAP GPT-4o组ASR高达98.9%，医疗eICU数据集ASR均值90%；仅MMLU问答因良性示例不足出现小幅业务衰减UD=-10%，医疗、电商场景UD接近0，投毒几乎不影响正常使用，隐蔽性极强。
2. **PSS渐进缩短必要性消融**
    移除PSS直接使用完整提示查询，ISR下降至75.6%；完整多轮缩短策略可生成大量高相似无污染提示记录，大幅提升检索召回概率，是攻击核心组件。
3. **嵌入模型与噪声鲁棒性**
    DPR、BGE、MiniLM、ada002全部嵌入架构下ISR均稳定90%以上；嵌入添加高斯噪声仅小幅降低ASR，证明攻击不依赖特定检索向量分布。
4. **良性样本密度影响**
    记忆内良性交互越多，MMLU问答ASR小幅下降；但医疗、电商垂直领域AS下降幅度极小，专业领域查询语义集中，污染记录更容易被召回。
5. **现有防御全部存在缺陷**
    - 针对性提示检测：仅能识别医疗固定句式，电商/问答场景检测率为0；
    - 通用检测：误报率高达34%，厂商无法大规模启用；
    - 嵌入聚类：污染与正常记录嵌入高度交织，无法分离；
    - 用户记忆隔离：攻击者可通过账号伪装绕过；
6. **方案局限**
    1. 仅针对共享记忆Agent，单用户独立记忆无攻击价值；
    2. 小参数量基础LLM（Llama2-7B）推理能力弱，攻击效果大幅衰减；
    3. 时序记忆衰减可缓慢降低ASR，但攻击者可持续补充污染记录维持威胁。

> 对应基本要求：实验覆盖医疗、电商、通用三类高风险Agent，完整消融检索、数据密度、PSS核心组件，同时验证市面主流防御均无法完全抵御，充分证明MINJA现实供应链风险。


# 《Memory Poisoning Attack and Defense on Memory Based LLM-Agents》结构化论文分析
## 一、问题：问题场景、问题描述、问题挑战
### 1. 问题场景
医疗EHR、企业办公等行业LLM Agent普遍采用**共享长期记忆架构**：全体用户交互记录统一存入全局记忆库，新查询时召回相似历史对话作为少样本示例。已有MINJA研究证明普通无权限用户仅通过前端查询即可投毒记忆，但原实验仅在**空干净记忆、理想极简环境**下完成验证，和真实生产系统差距极大；现实医疗Agent会长期积累海量合法患者交互记录，检索条数、攻击提示数量等核心变量动态变化，MINJA在真实存量记忆下的攻击有效性未知，同时缺少适配医疗高风险场景的分层防御方案，现有防护无法平衡安全与业务可用性。

### 2. 问题描述
本文以医疗电子病历EHR Agent为核心高风险实验场景，围绕MINJA记忆投毒攻击开展**真实环境系统性复现与量化评估**，填补理想环境与工业部署的研究空白；
1. 攻击侧：控制「存量合法记忆、诱导提示条数、检索记忆数量」三大现实变量，证明真实系统中大量良性历史样本会大幅削弱MINJA攻击成功率，拆解攻击失效底层机理；
2. 防御侧：提出两套分层互补防护机制：
    - 输入输出联合校验（Input/Output Moderation）：多维度复合信任打分，前置拦截恶意查询，拒绝低可信交互存入记忆；
    - 带时效衰减的可信记忆清洗（Trust-Aware Memory Sanitization）：记忆入库、检索双阶段打分，老旧低信任样本自动衰减过滤；
实验对比GPT-4o-mini、Gemini-2.0-Flash、Llama3.1三类主流模型，发现防御存在模型适配缺陷：弱小模型防御偏保守易损失业务能力，强推理大模型易被精巧诱导指令欺骗，出现高置信度恶意记忆入库漏洞。

### 3. 问题挑战
1. **真实环境空白**：现有MINJA仅在空白记忆测试，未建模长期积累的存量合法交互记录对投毒的抑制作用；
2. **多变量耦合量化难**：存量记忆、诱导提示数量、检索top-k值三者互相影响，缺少单一变量控制对照实验；
3. **高风险场景适配**：医疗场景投毒会导致病历混淆、误诊，防御不能一刀切拒绝所有交互，必须严控假阳性、保证诊疗可用性；
4. **模型差异化防御缺陷**：小型基础模型、高级推理大模型对恶意指令识别能力完全不同，统一防御阈值会出现过拒/漏毒两极问题；
5. **长效记忆治理**：静态校验只能拦截入库攻击，无法处理长期留存的老旧污染样本，需要时序衰减机制；
6. **安全效用权衡**：防御不能过度过滤正常问诊查询，否则大幅降低医生使用效率。

> 对应基本要求：承接MINJA基础攻击研究，聚焦**医疗生产级Agent真实存量记忆场景**，核心痛点是原攻击评估脱离工业环境、缺少分阶段适配型记忆防御方案。

## 二、现有工作及不足：现有工作核心思路、存在的问题、根本原因
### 1. 现有工作核心思路
1. MINJA（前置论文）：提出纯查询记忆投毒，在空白理想记忆下验证高ASR，但未测试带存量真实系统；
2. AgentPoison：攻击者拥有后台直接修改记忆权限，攻击门槛过高，不符合普通用户威胁模型；
3. RAG/知识库投毒（BadRAG、PoisonedRAG）污染静态文档，不针对Agent动态交互记忆；
4. 基础输入检测防御（Llama Guard、DRIFT）仅做单轮输入关键词过滤，无记忆入库、检索全链路管控；
5. A-MemGuard：依赖底层内存权限校验，黑盒API商用Agent无法部署；
6. 记忆时序、信任相关研究：无针对MINJA类隐蔽ID跳转投毒的专用打分清洗方案。

### 2. 存在的问题
1. 攻击评估脱离工业现实：全部记忆投毒基准实验采用空初始记忆，无法复现线上大量合法样本稀释攻击的真实效果；
2. 防御链路残缺：现有防护仅拦截输入，未对存入记忆、检索召回两个关键环节做二次可信校验；
3. 模型泛化缺失：未区分强弱LLM对恶意诱导的耐受差异，一套阈值无法适配所有基座；
4. 缺少行业落地验证：通用Agent防御未在医疗EHR高风险场景做假阳性、误诊风险专项评测；
5. 无长效治理手段：仅拦截新污染，历史老旧恶意记忆会持续劫持后续问诊查询。

### 3. 根本原因
过往记忆攻防研究割裂「理想实验室环境」与「长期运行生产系统」，未意识到存量合法交互会通过相似检索稀释污染样本权重；同时防御设计只关注输入单一层面，忽略**记忆入库持久化、检索召回少样本引导**两大攻击生效关键环节，且未针对不同推理能力模型设计差异化信任阈值。

## 三、方案：方案动机、方案整体思路、关键步骤、关键技术
### 1. 方案动机
MINJA仅在空白记忆验证，无法衡量真实医疗Agent的实际投毒风险，且市面现有防御无法全链路管控动态交互记忆。本文先系统量化三大现实变量对MINJA攻击的抑制效果，再设计「输入输出前置拦截+记忆时序可信清洗」双层防御，兼顾新攻击拦截与存量污染长效治理，适配强弱不同大模型，在医疗病历场景平衡安全与诊疗可用性。

### 2. 方案整体思路
整体分为两大模块：
模块1：真实环境MINJA攻击量化评估
控制存量合法记忆、诱导提示条数、检索top-k三个变量，在GPT4o-mini、Llama3.1复现投毒实验，分析存量样本稀释、检索条数提升对ASR/ISR的影响规律；
模块2：双层递进防御流水线
1）前置输入输出联合校验：静态关键词+语义分类+代码安全多信号复合信任打分，低分交互直接禁止存入记忆；
2）记忆层可信清洗：入库时赋予基础信任分，随时间时序衰减，检索时过滤低分老旧记录，同时匹配ID跳转类攻击模板二次拦截。

### 3. 关键步骤
#### 模块1：攻击变量对照实验
1. 基线对照组：完全空白初始记忆，2轮诱导提示，检索top=3；
2. 存量记忆实验组：加入6条合法患者交互记录，保持其余参数不变；
3. 诱导提示消融：将2轮提升至4轮，观察ISR/ASR变化；
4. 检索条数消融：top=3→5→10，量化召回更多样本对攻击成功率的提升效果；
5. 多模型横向对比GPT4o-mini、Llama3.1，分析模型推理能力对攻击敏感度差异。

#### 模块2：双层防御执行流程
1. 输入校验：匹配`refer/map/merge`等跳转关键词，可疑样本调用LLM语义打分，低分直接阻断模型推理；
2. 输出校验：解析生成SQL病历代码，检测患者ID重定向逻辑，复合信任分低于阈值禁止写入记忆；
3. 记忆入库打分：结合输入、输出、代码三重校验结果生成基础信任值；
4. 时序衰减：记忆随使用时长自动降低有效信任分；
5. 检索过滤：召回时剔除低于阈值的老旧低可信记录，仅高置信样本作为少样本示例。

### 4. 关键技术
1. **三变量控制量化评估框架**：首次拆解存量记忆、诱导提示、检索条数三大现实干扰因子，精准刻画真实系统投毒风险衰减规律；
2. **多信号复合信任打分机制**：融合静态关键词、语义理解、数据库代码三层正交信号，降低单一检测漏报率；
3. 双层递进防御架构：前置拦截阻断新污染入库，后置时序清洗治理历史恶意记忆；
4. 行业专属攻击模板匹配：针对医疗患者ID跳转类MINJA载荷设计专用过滤规则；
5. 时序衰减可信检索：解决静态防御无法处理长期留存污染样本的痛点。

> 对应基本要求：动机补齐MINJA真实场景评估短板，流程分为攻击量化、双层防御两大模块，每项技术分别解决现实变量量化、全链路记忆管控、长效污染治理三大核心挑战。

## 四、实验：实验数据、对比方法、评价标准、参数设置、实验数据分析
### 1. 实验数据与环境
1. 测试Agent：EHR电子病历医疗Agent，数据集MIMIC-III；
2. 基座模型：GPT-4o-mini、Llama-3.1-8B-Instruct、Gemini-2.0-Flash；
3. 攻击素材：50套患者ID映射类MINJA诱导提示，5组受害者/目标病历ID配对；
4. 记忆配置：空初始记忆、含6条合法存量记忆两组基线；
5. 防御对照组：无防护、仅输入过滤、完整输入输出+记忆清洗双层防御。

### 2. 对比/消融实验组
1. 攻击消融：有无存量合法记忆、诱导提示2/4条、检索top-k=3/5/10；
2. 模型横向对比：GPT4o-mini、Llama3.1、Gemini；
3. 防御消融：仅输入校验、完整双层防御；
4. 基线对比：原生无防护Agent。

### 3. 评价标准
1. 攻击指标
    - ISR注入成功率：攻击交互成功存入记忆占比；
    - ASR攻击触发率：受害者查询时模型错误跳转病历比例；
2. 效用指标
    - 良性任务准确率：正常问诊病历查询正确率；
    - 假阳性FP：合法交互被拦截比例（越低越好）；
3. 防御指标
    - 污染拦截率：恶意交互被阻断无法入库占比；
    - 记忆漏毒率：恶意样本成功存入记忆比例。

### 4. 参数设置
1. MINJA攻击：渐进缩短诱导提示2~4轮，检索top3/5/10；
2. 存量记忆配置：4条无关通用问诊+2条受害者合法病历记录；
3. 信任阈值默认0.5，时序衰减随存储轮次线性降低分值；
4. 攻击集总计101条病历ID跳转类诱导查询。

### 5. 实验数据及分析
#### （1）存量记忆核心抑制结论
空白记忆基线：GPT4o-mini ASR=62%、Llama3.1 ASR=52.94%；
加入6条合法存量记忆后：GPT4o-mini ASR暴跌至6.67%，Llama3.1 ASR直接降至0；
机理：检索时大量正常病历示例稀释污染样本权重，模型优先学习合法ID映射逻辑，验证Hypothesis1成立。

#### （2）诱导提示条数消融
仅增加诱导提示从2轮至4轮，ISR、ASR无明显提升，原假设2不成立；
原因：Levenshtein相似度检索优先匹配仅含受害者ID的合法样本，新增污染记录相似度不占优势。

#### （3）检索条数top-k消融
检索数量从3提升至10，ASR持续上涨：
- GPT4o-mini：6.67% → 13.33% → 38%
- Llama3.1：0% → 13.33% → 27.27%
更多召回样本会混入污染记录，上下文噪声提升攻击概率，验证Hypothesis3成立。

#### （4）模型差异化攻击表现
Llama小模型推理能力弱，存量记忆下几乎不会被投毒；Gemini强模型易被精巧诱导指令欺骗，大量恶意交互取得满分1.0信任分，防御出现严重漏毒；GPT4o-mini防御偏保守，全部攻击交互信任分低于0.5直接拦截。

#### （5）双层防御效果对比
1. GPT4o-mini环境：双层记忆清洗将全部101条恶意查询拦截，记忆无任何污染，缺陷是少量正常问诊也被拒绝，诊疗可用性下降；
2. Gemini环境：前置输入过滤拦截45.7%攻击，但剩余54.3%恶意交互被赋予满分信任存入记忆，时序衰减无法挽回已入库污染，强推理模型存在防御逃逸漏洞；
3. 仅单输入过滤基线：漏毒率超50%，无法阻止污染持久留存，证明记忆层清洗是必要第二防线。

#### （6）方案局限
1. 防御效果高度依赖基座LLM推理能力，强大模型易被精心设计的隐蔽诱导指令欺骗；
2. 保守阈值下会产生业务假阳性，医疗问诊场景可用性受损；
3. 仅针对患者ID映射类MINJA攻击，未覆盖药品、诊疗方案类记忆投毒载荷。

> 对应基本要求：完整验证三大现实变量对记忆投毒的抑制效果，对比三类主流模型暴露防御模型适配缺陷，双层防御的优劣、取舍全部通过量化数据支撑，同时点明医疗行业落地局限性。



# 《Autonomy Comes with Costs: Detecting Denial-of-Service Vulnerabilities Caused by Resource Abusing》结构化论文分析
## 一、问题：问题场景、问题描述、问题挑战
### 1. 问题场景
当下开源LLM智能Agent（AutoGPT、Dify、LangFlow、DB-GPT等）广泛集成文件下载、网页解析、数据库查询、多轮会话记忆等工具，具备自主执行用户自然语言任务的能力。开发者为保证任务完整性，普遍缺少系统资源（内存、磁盘）生命周期管控逻辑：大量临时文件、会话历史、解析缓存无自动回收机制，攻击者仅通过普通对话接口提交语义合法恶意prompt，即可持续耗尽服务器内存/磁盘，引发资源耗尽型DoS，造成服务瘫痪、算力损耗。现有模糊测试工具仅针对传统正则、CPU类DoS，无法生成符合Agent语义的攻击提示，也未区分会话/全局三类资源生命周期，无法完整挖掘Agent专属资源滥用漏洞，行业缺少专用检测框架。

### 2. 问题描述
本文完成业界首个LLM Agent资源耗尽DoS系统性安全研究：
1. 归纳Agent三类资源生命周期：短时资源（单轮对话执行后GC回收）、长时资源（会话存续，会话销毁释放）、全生命周期资源（创建后永久留存，无清理逻辑），三类生命周期对应完全不同攻击路径；
2. 提出定向灰盒模糊测试框架AgentDoS，分为静态建模、动态模糊两大阶段：静态CodeQL代码分析定位可被用户输入控制的内存/磁盘高危操作，自动判别资源生命周期；大模型辅助生成贴合工具语义、可触发超大资源占用的种子prompt，搭配双变异器迭代优化载荷，并根据资源生命周期采用差异化调度策略发包；
3. 在20款主流开源Agent完成实测，挖出36个0day资源滥用漏洞，15个已分配CVE；对比基线AgentFuzz召回率提升12倍，精确率100，可复现单轮爆内存、多轮累积占满磁盘两类真实攻击。

### 3. 问题挑战
1. **资源生命周期自动识别难**：Agent无统一资源管理框架，自定义会话、文件缓存逻辑分散在业务代码，静态分析难以自动判别资源释放时机；
2. **语义合规攻击prompt生成难**：传统二进制模糊测试仅做位翻转，无法生成“下载超大文件、嵌套深度HTML”等符合Agent工具语义的恶意自然语言指令；
3. **差异化发包调度约束**：三类生命周期漏洞利用方式完全不同——短时单轮打满资源、长时同会话累积、全生命周期新建会话反复投放，统一测试策略会大量漏报；
4. **真实工业泛化要求**：覆盖上万Star主流开源Agent，检测工具需适配Python各类IO、容器、会话存储API；
5. **漏洞判定无标准Oracle**：需实时监控服务器内存、磁盘占用，精准识别服务无响应的DoS触发临界点，区分正常大任务与攻击。

> 对应基本要求：聚焦工具型LLM Agent独有的资源管理漏洞，区别传统Web/CPU DoS、Agent提示注入研究，核心痛点是现有检测工具不懂Agent语义、未区分资源生命周期，无法挖掘资源耗尽型拒绝服务漏洞。

## 二、现有工作及不足：现有工作核心思路、存在的问题、根本原因
### 1. 现有工作核心思路
1. 传统软件DoS检测（ReDoS、内存泄漏Fuzzer）：针对正则、循环CPU、底层内存漏洞，输入为代码/字符流，无法处理自然语言prompt输入；
2. LLM推理层DoS（超长文本、对抗输入拖慢推理）：攻击基座模型推理耗时，不针对Agent上层工具、文件存储逻辑；
3. Agent模糊测试AgentFuzz：仅面向污点注入漏洞，无资源占用打分机制，不会生成耗资源载荷，不区分资源生命周期；
4. Agent安全研究（提示注入、间接注入、越狱）：聚焦指令劫持、隐私泄露，完全忽略资源耗尽DoS攻击面；
5. Agent资源优化工程工作：仅提升执行效率，无漏洞挖掘、红队检测能力。

### 2. 存在的问题
1. 输入范式不匹配：传统模糊测试无法生成自然语言语义攻击prompt，只能做底层字节变异，对Agent失效；
2. 缺失生命周期建模：所有Agent安全检测未区分短时/长时/全局资源，统一发包策略会大面积漏报累积型DoS；
3. 无资源占用评估机制：现有工具不会量化prompt带来的内存/磁盘开销，无法迭代优化高消耗攻击载荷；
4. 攻击目标单一：AgentFuzz仅检测污点泄露，不覆盖文件下载、网页解析、会话缓存等资源高危接口；
5. 缺少大规模真实Agent实证：过往Agent安全实验仅1-2款小型Demo，未覆盖AutoGPT、Dify等线上商用级开源项目。

### 3. 根本原因
过往LLM Agent安全研究重心集中在指令劫持、数据泄露，忽视**自主工具调用带来的系统资源权限暴露**；传统DoS模糊测试无法适配自然语言输入场景，且业界未意识到资源生命周期是决定攻击方式的核心变量，缺少「静态代码生命周期解析+LLM语义生成+生命周期感知调度」一体化检测范式。

## 三、方案：方案动机、方案整体思路、关键步骤、关键技术
### 1. 方案动机
现有模糊测试无法生成语义合规Agent攻击提示，也未区分三类资源生命周期，大量磁盘/内存耗尽0day漏洞无法被检出。本文设计AgentDoS定向灰盒模糊框架，通过静态代码分析自动识别资源生命周期，大模型生成耗资源prompt，搭配生命周期差异化发包策略，高效挖掘Agent资源滥用DoS漏洞，填补该细分安全检测空白。

### 2. 方案整体思路
框架分为两大独立核心模块：
1. 高危算子静态建模模块：基于CodeQL做跨过程污点分析，定位可被用户输入控制的内存容器、磁盘写入API；解析会话销毁、变量回收逻辑自动区分短时/长时/全生命周期资源，过滤有严格大小限制、用户不可控的安全操作；输出漏洞候选算子、代码片段、调用链；
2. 动态模糊测试模块：运行时抓取Agent系统提示，大模型生成功能匹配种子prompt；从功能对齐、资源消耗双维度打分筛选优质种子，Explorer/Exploiter双变异器迭代优化载荷；根据资源生命周期选择发包模式（短时/全局新建会话、长时固定会话），实时监控资源占用，服务无响应即判定漏洞。

### 3. 关键步骤
#### 模块1 静态高危算子建模
1. 定义内存/磁盘两类高危Sink：list/dict追加、文件写入、HTML深度解析等接口；
2. 构造控制流图，污点追踪用户输入是否可控流入Sink；
3. 分析变量作用域、会话销毁代码自动判定资源生命周期；
4. 反向数据流查找大小阈值校验逻辑，过滤受保护安全接口；
5. 输出全部可利用高危算子，附带代码片段、生命周期标签。

#### 模块2 动态模糊测试
1. 运行时Hook LLM接口抓取完整系统提示，解析可用工具功能；
2. 结合静态调用链，CoT大模型生成初始功能匹配种子prompt；
3. 执行prompt，从功能匹配度、资源消耗双维度计算种子综合得分；
4. Explorer变异器优化工具调用语义，Exploiter嵌入超大/嵌套资源链接提升资源开销；
5. 按生命周期调度发包：短时/全局新建会话，长时复用单会话累积资源；
6. psutil实时监控内存磁盘，服务超时判定DoS漏洞，输出完整攻击PoC对话。

### 4. 关键技术
1. **CodeQL驱动资源生命周期静态判别**：通过变量作用域、会话销毁分支自动区分三类资源，无需人工标注；
2. **LLM辅助语义种子生成+双变异器迭代优化**：解决传统模糊无法生成自然语言攻击指令的痛点；
3. **双维度种子打分机制**：同时衡量工具调用成功率、资源消耗幅度，优先筛选高效攻击载荷；
4. **生命周期感知差异化发包调度**：针对三类漏洞采用完全不同交互策略，大幅降低漏报率；
5. **资源监控漏洞判定Oracle**：实时采集服务器硬件指标，以服务无响应作为漏洞客观判定标准，无主观打分偏差。

> 对应基本要求：动机解决传统模糊不兼容Agent语义、无生命周期建模两大短板，流程分静态代码分析、动态模糊两大阶段，每项技术分别解决漏洞定位、攻击生成、调度策略、漏洞判定四大核心挑战。

## 四、实验：实验数据、对比方法、评价标准、参数设置、实验数据分析
### 1. 实验数据与环境
1. 被测Agent数据集：20款主流开源项目（AutoGPT、Dify、LangFlow、DB-GPT等），覆盖5k~176k GitHub Star；
2. 模型：GPT-4.1用于AgentDoS的prompt生成与打分；
3. 漏洞基准：38个经人工核验的资源DoS真实漏洞（AgentDoS检出36、AgentFuzz仅3个）；
4. 外部恶意资源：预制超大文件URL、多层嵌套HTML/XML链接用于载荷嵌入。

### 2. 对比/消融实验组
1. 基线工具：AgentFuzz（现有唯一Agent模糊框架）；
2. 消融对照组：关闭种子生成、关闭种子调度、关闭双变异器三个框架删减版本；
3. 变量消融：不同资源生命周期、不同Agent项目、单轮测试时长上限20分钟。

### 3. 评价标准
1. 漏洞检测指标
    - TP真漏洞数量、FP误报、FN漏报；
    - Precision精确率、Recall召回率；
2. 效率指标
    - 平均单Agent测试CPU耗时、单漏洞平均挖掘轮次、总token消耗；
3. 漏洞质量指标
    - 单轮短时DoS成功率、多轮累积资源上涨幅度。

### 4. 参数设置
1. 静态分析：CodeQL构建全量控制流、跨过程污点追踪；
2. 动态模糊：单Sink测试时限20分钟，资源上涨阈值20MB/3分钟；
3. 打分权重α=0.5（功能分）、β=0.5（资源分）；
4. 温度=0保证LLM生成确定性；Docker隔离Agent容器，硬件资源固定4G内存10G磁盘。

### 5. 实验数据及分析
#### （1）基线对比核心结论
AgentFuzz仅检出3个漏洞，召回率7.9%；AgentDoS检出36个0day，精确率100%、召回率94.7%，性能提升12倍。根源：AgentFuzz无生命周期区分，不会生成耗资源prompt，只能挖掘少量单轮简单漏洞。

#### （2）消融实验组件必要性
- 关闭种子生成：召回降至81.6%，大量prompt无法触发目标工具；
- 关闭打分调度随机选种子：召回65.7%，重复低效载荷浪费测试时间；
- 移除双变异器仅用初始种子：召回仅42.1%，无法构造超大资源消耗指令；
三大模块缺一不可，变异器对挖掘累积型磁盘漏洞增益最大。

#### （3）资源生命周期实验差异
1. 短时资源：单轮prompt即可打满内存，攻击链路短、PoC简洁；
2. 长时资源：必须固定同会话多轮交互累积缓存，新建会话策略完全失效；
3. 全生命周期：反复新建会话下载文件，磁盘永久累加无法自动清理，危害最持久；
静态分析生命周期识别整体准确率95.2%，仅少量间接动态调用出现识别误差。

#### （4）漏洞真实危害验证
1. 短时案例：单轮请求循环拉取1000次超大HTML，本地列表爆内存直接服务卡死；
2. 长时案例：持续会话追加大量对话历史缓存，内存线性上涨直至OOM；
3. 全局案例：下载文件永久留存磁盘，多攻击者多会话循环占用存储空间；
15个高危漏洞已分配官方CVE编号，厂商确认风险并上线文件大小、会话配额防护。

#### （5）方案局限
1. 依赖Agent源代码，闭源商用GPTs、Coze等黑盒Agent无法直接静态分析；
2. 部分漏洞需要极长时间累积资源，20分钟时限会少量漏报；
3. 仅覆盖内存、磁盘两类资源，未针对CPU、网络带宽耗尽场景建模。

> 对应基本要求：实验覆盖20款工业级开源Agent，完整基线对比+三模块消融实验，分三类生命周期量化攻击效果；实验数据充分证明AgentDoS在语义生成、生命周期调度上的核心优势，同时客观指出源码依赖、测试时长等落地局限。
